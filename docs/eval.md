# Evaluation Engine

DeepVault features a robust, automated evaluation engine designed to rigorously test and compare our various retrieval and chunking strategies. We do not guess whether an architecture change improves the system — we measure it.

## The Approach: LLM-as-a-Judge

We use an LLM-as-a-Judge approach. Specifically, we use a high-capacity model (`llama-3.3-70b-versatile`) to evaluate the outputs generated by the standard pipeline models. The evaluator looks at the user query, the retrieved context, and the generated answer, and scores the performance based on strict rubrics.

## Metrics Tracked

The evaluation pipeline measures five key metrics:

1. **Faithfulness (1-5 Scale)**: Does the generated answer accurately reflect the retrieved context? A score of 5 means the answer is perfectly grounded in the context.
2. **Hallucination Rate (%)**: What percentage of answers contain information not present in the retrieved context?
3. **Precision at K (P@K)**: Out of the top K retrieved chunks, how many were actually relevant to answering the query?
4. **Hit Rate (CP@1)**: Was a highly relevant chunk present in the very first position?
5. **Cost Efficiency**: How many tokens were consumed during the retrieval and generation process, and what is the estimated cost per 1k queries?

## Running Evaluations

The evaluation scripts are located in `scripts/eval/` (currently being restructured). To run an evaluation pass:

```bash
# Evaluate a specific configuration
uv run python scripts/eval/runner.py --retrieval hybrid --chunking sliding

# Run the full benchmark suite across all combinations
uv run python scripts/eval/benchmark.py
```

## Strategy Matrix

A full benchmark run tests 24 combinations:
- **6 Retrieval Strategies:** `vector`, `bm25`, `hybrid`, `hybrid_rerank`, `vector_rewrite`, `hybrid_rewrite`
- **4 Chunking Strategies:** `fixed`, `sliding`, `structure`, `semantic`

## Continuous Improvement

The benchmark results are output as structured JSON to `data/eval_runs/` (and soon to Langfuse), where they can be analyzed using the Streamlit dashboard (`Metrics Laboratory`). When proposing an algorithmic change to DeepVault, developers must run the evaluation engine and prove a statistically significant improvement in Faithfulness or Hallucination Rate before merging.
